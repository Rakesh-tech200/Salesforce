Phase 5: Flows, validation rules and the approval process
Build order: the approval formula → validation rules → four small flows → test them → Create Order flow → approval process → final tests.
For every flow: Setup → Flows → New Flow. Save it with the exact Label and API Name I give, then click Activate.
Click + on the canvas to add an element. Name each element with the Label I give. The API name auto-fills, and you must keep it.
My formulas assume the Paid status API value is Paid. If yours differs, tell me before you start.
Step 5.1: Order formula "Needs Approval"
Object Manager → Order → Fields & Relationships → New → Formula → Next.
Label: Needs Approval, Name: Needs_Approval, Return type: Checkbox. Click Next.
Formula:
Max_Discount__c > MAX($CustomMetadata.Blush_Setting__mdt.Default.Approval_Discount_Limit_Pct__c, Approved_Max_Discount__c)
Check Syntax → Next → Next → Save.
Open Retail Order Layout and Wholesale Order Layout. Drag Needs Approval into the Totals and Commission section and set it Read-Only (wrench icon). Save each layout.
It is true only when a line's discount is above the 10% limit and above the level already approved.
Step 5.2: Validation rules
For each rule: Object Manager → [object] → Validation Rules → New. Tick Active. Paste the formula and enter the message. Error Location is Top of Page unless I say otherwise.
Opportunity (4 rules)
Customer_Name_Required: Location: field Customer Name
AND(OR(ISNEW(), ISCHANGED(Customer_Name__c)), ISBLANK(Customer_Name__c))
Message: Customer Name is required.
Customer_Email_Or_Phone_Required
AND(ISNEW(), ISBLANK(Customer_Email__c), ISBLANK(Customer_Phone__c))
Message: Enter at least one of Customer Email or Customer Phone.
Pricebook_Must_Match_Record_Type
AND(
  NOT(ISBLANK(Pricebook2Id)),
  OR(
    AND(RecordType.DeveloperName = "Retail", Pricebook2.Name <> "Retail Price Book"),
    AND(RecordType.DeveloperName = "Wholesale", Pricebook2.Name <> "Wholesale Price Book")
  )
)
Message: Retail opportunities must use the Retail Price Book and wholesale ones the Wholesale Price Book.
Account_Record_Type_Must_Match
AND(NOT(ISBLANK(AccountId)), Account.RecordType.DeveloperName <> RecordType.DeveloperName)
Message: The Account's record type must match the Opportunity's record type.
If the syntax check rejects Pricebook2.Name, use Insert Field → Price Book → Price Book Name instead and tell me what it inserted.
Order (7 rules)
Account_Record_Type_Must_Match_Order
AND(NOT(ISBLANK(AccountId)), Account.RecordType.DeveloperName <> RecordType.DeveloperName)
Message: The Account's record type must match the Order's record type.
Pricebook_Must_Match_Order_Record_Type
AND(
  NOT(ISBLANK(Pricebook2Id)),
  OR(
    AND(RecordType.DeveloperName = "Retail", Pricebook2.Name <> "Retail Price Book"),
    AND(RecordType.DeveloperName = "Wholesale", Pricebook2.Name <> "Wholesale Price Book")
  )
)
Message: Price book does not match the order's record type.
Store_Required_To_Confirm: Location: field Store
AND(OR(ISPICKVAL(Status,"Confirmed"), ISPICKVAL(Status,"Paid")), ISBLANK(Store__c))
Message: Select a Store before confirming or paying the order.
Payment_Mode_Required_To_Confirm: Location: field Payment Mode
AND(OR(ISPICKVAL(Status,"Confirmed"), ISPICKVAL(Status,"Paid")), ISPICKVAL(Payment_Mode__c, ""))
Message: Select a Payment Mode before confirming or paying the order.
Billing_State_Required_To_Confirm
AND(OR(ISPICKVAL(Status,"Confirmed"), ISPICKVAL(Status,"Paid")), ISBLANK(BillingState))
Message: Enter the Billing State before confirming or paying the order (it decides CGST/SGST vs IGST).
Lines_Required_To_Confirm
AND(OR(ISPICKVAL(Status,"Confirmed"), ISPICKVAL(Status,"Paid")), Line_Count__c = 0)
Message: Add at least one product before confirming or paying the order.
Discount_Approval_Required
AND(OR(ISPICKVAL(Status,"Confirmed"), ISPICKVAL(Status,"Paid")), Needs_Approval__c)
Message: A line discount is above the approval limit. Submit the order for manager approval first.
Order Product (3 rules)
Unit_Price_Must_Equal_List_Price
AND(NOT(ISBLANK(ListPrice)), UnitPrice <> ListPrice)
Message: Unit Price comes from the price book. Use Discount % to give a discount.
Discount_Between_0_And_100: Location: field Discount %
OR(Discount_Percent__c < 0, Discount_Percent__c > 100)
Message: Discount % must be between 0 and 100.
Quantity_Whole_Number: Location: field Quantity
OR(Quantity < 1, Quantity <> FLOOR(Quantity))
Message: Quantity must be a whole number of at least 1.

Step 5.4: Flow 2, Order Product calculations
New Flow → Record-Triggered Flow. Object: Order Product. Trigger: A record is created or updated. Entry conditions: None (always run). Run: Every time a record is updated and meets the condition requirements. Optimize for: Fast Field Updates.
+ → Get Records: Label Get Setting. Object: Blush Setting. Filter: Developer Name Equals Default. Store: Only the first record. Fields: all.
Create these Formula resources. Each is Data Type: Number, Decimal Places: 2.
API Name
Formula
fDiscountAmt
ROUND({!$Record.UnitPrice} * BLANKVALUE({!$Record.Discount_Percent__c}, 0) / 100, 2)
fDiscountedUnit
{!$Record.UnitPrice} - {!fDiscountAmt}
fTaxable
ROUND({!fDiscountedUnit} * {!$Record.Quantity}, 2)
fGstRate
IF({!$Record.PricebookEntry.Product2.Category__c} = "Jewellery", {!Get Setting.Jewellery_GST_Pct__c}, IF({!fDiscountedUnit} > {!Get Setting.Garment_GST_Threshold__c}, {!Get Setting.Garment_GST_High_Pct__c}, {!Get Setting.Garment_GST_Low_Pct__c}))
fGstAmt
ROUND({!fTaxable} * {!fGstRate} / 100, 2)
fCgst
IF({!$Record.Order.Intra_State__c}, ROUND({!fGstAmt} / 2, 2), 0)
fSgst
IF({!$Record.Order.Intra_State__c}, {!fGstAmt} - {!fCgst}, 0)
fIgst
IF({!$Record.Order.Intra_State__c}, 0, {!fGstAmt})
fNet
{!fTaxable} + {!fGstAmt}
fCost
ROUND({!$Record.PricebookEntry.Product2.Cost_Price__c} * {!$Record.Quantity}, 2)
